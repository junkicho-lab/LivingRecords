# 생각 포착·정리 앱 — 컨셉 (토론 기록)

> 작성: 2026-06-04 · 갱신: 2026-06-04 · 상태: **v1 구현 완료 (S0~S7, git 커밋됨)** — 슬라이스는 docs/v1-slices.md
> 앱 이름: **생동하는 기록** (Living Record)
> 이 문서는 설계 토론에서 *결정된 것*과 *미결*을 기록한다. 결정이 바뀌면 갱신.

---

## 0. 한 줄 정의

> **말로 쏟아낸 생각을 로컬에 모아두면, AI가 분석·분류·정리해 '가공된 글'(일/주/기간 템플릿)로 만들고, 결국 "내가 무엇을 지속할 것인가"를 돕는 앱.**

## 1. 핵심 루프

```
포착(말) → 저장(텍스트, 로컬) → AI 분석·분류 → 가공(템플릿: 일/주/기간) → 회고·결정(무엇을 지속?)
                                                                    ↘ 결정이 다음 회고로 피드백
```

## 2. 차별점 / 해자

- 흔한 "음성 메모 + AI 요약"과 다른 한 가지: **"앞으로 무엇을 지속할 것인가"를 돕는다.**
- 진짜 해자: **음성**이라서 *목소리의 결(에너지)*을 읽을 수 있다 — 텍스트 일기 앱은 못 하는 것.
- 기계는 **판결하지 않는다.** 증거를 제시 → **사람이 결정** → 그 결정이 데이터가 되어 다음을 똑똑하게.

## 3. 결정된 사항 ✅

### 3-1. 프라이버시: 하이브리드
- **포착·저장은 로컬**, **가공만 선택적으로 클라우드**.
- 원칙: **클라우드를 한 번도 안 켜도 앱은 쓸모 있어야 한다**(클라우드는 의존이 아니라 업그레이드).
  - 로컬 담당: 포착(STT) + 저장 + 분류/태깅/통합 + **일일 가벼운 정리**
  - 클라우드 담당: 주간·기간의 **깊은 종합**(추세·반복·연결·지속 제안)

### 3-2. 2단계 증류 (원문은 로컬 봉인)
```
[로컬] 원문(verbatim) ──로컬 LLM──▶ 증류층(주제·요약·키워드)
                                       └─(켤 때만)──▶ [클라우드] 깊은 종합
```
- **날것의 말(원문)은 절대 기기를 떠나지 않는다.** 클라우드로 가는 건 로컬이 추상화한 *증류층*뿐.

### 3-3. 클라우드 동의 모델: "한 번 켜기 / 봉인 예외 / 사후 열람" (매번 묻지 않음)
1. **한 번 설정** — "깊은 종합은 클라우드 허용" 스위치(기본 OFF, 켜는 건 의식적으로 한 번).
2. **봉인(예외)** — 포착할 때 *진짜 사적*이면 그 자리에서 **봉인**. 봉인된 포착·주제는 전역 스위치가 켜져도 클라우드로 안 감. (포착 트리거에 흡수 — 아래 3-4)
3. **전송 로그** — "언제 무엇이 클라우드로 나갔나"를 언제든 볼 수 있게(사전 차단 대신 사후 감사).

### 3-4. 포착 (Capture) — 마찰 0
- **원칙: 포착 = 한 동작, 결정 0개.** 말하고 끝. 분류·태깅·정리는 전부 나중에 AI가.
  - 포착 화면 = 녹음 버튼 + 텍스트칸 + 끝. **분류 UI 없음.**
- **주 기기: 폰(이동 중) 1순위** → 모바일 우선. **플랫폼: iOS 우선**(Android 나중).
- **트리거(v1): 홈/잠금화면 위젯 한 탭**. 액션버튼·AirPods 꾹은 *나중 업그레이드*.
  - ~~항상 듣기~~ 탈락 — 프라이버시 + 포착은 *의도적* 행위.
  - **봉인 = 트리거에 흡수**: 탭=일반 / 꾹누르기=봉인 (둘 다 한 제스처). 봉인은 사후 로그에서도 가능.
- **말한 직후**: 즉시 저장(fire-and-forget). STT·prosody·오디오 폐기는 **백그라운드**. 확인은 조용한 신호(진동 등).
- **텍스트 폴백**: 음성 우선, 텍스트는 항상 가능(회의·공공장소 대비).

### 3-5. 분류 체계 — emergent + 통합
- **여기서 분류 = "폴더에 넣기"가 아니라 "주제(Theme)로 묶기"** = 반복 신호의 토대.
- 고정 틀 ✗ (생각 범주를 미리 예측 못 함 + 발견을 죽임 + 포착 마찰). 순수 emergent도 ✗ (라벨 표류로 반복 카운트 깨짐).
- **답: AI가 자유롭게 주제 부여 → 임베딩 유사도로 비슷한 것 병합해 안정된 Theme.** 아래에서 자라는 + 자기 병합. **로컬에서**.
- **축은 하나(주제)**. 유형/감정 결은 신호(맴돎/진화/에너지)가 담당.
- **사용자 큐레이션 v1 포함**: 주제 이름변경·합치기·나누기·고정. (AI 통합 불완전 + 반복 정확도가 주제 경계에 달림). 교정도 피드백 데이터.

### 3-6. "지속할 것"을 알아채는 신호 (전체 5개)
1. **반복** — *진화하는 반복*(말할수록 생각이 자람=살아있음) vs *맴도는 반복*(같은 말 되풀이=교착·걱정). **이 구분이 앱의 지능.**
2. **에너지** — 목소리의 결로 읽는 흥분/몰입 (해자).
3. **실행 추적** — "하겠다"가 나중에 살아남았는가.
4. **연결** — 멀리 떨어진 생각이 한 줄기로 모이는 순간(영감).
5. **냉각** — 뜨거웠다 식은 주제. *접을 것*도 알아채야 함(지속 = 이어가기 + 가지치기).

### 3-7. v1 신호 범위
- **v1: 반복(진화/맴돎) + 에너지** 만. (데이터가 적어도 바로 작동)
- 다음 단계: 실행 추적 · 연결 · 냉각 (쌓여야 의미 생김).

### 3-8. 에너지 출처: 절충안 C (포착 순간 점수만, 오디오 폐기)
```
말함 → [포착 순간, 로컬]
        ├─ STT로 텍스트 추출 ──────────▶ 저장
        ├─ prosody 요약치(에너지 점수 1~2개) 추출 ─▶ 저장
        └─ 오디오 원본 즉시 폐기 ✗
```
- 목소리 기반 에너지(해자)는 **확보**, 가장 민감한 오디오는 **안 쌓음**(프라이버시 유지), 용량 부담 없음.
- 언어 기반 신호(긍/부정 방향)는 텍스트에서 얹음 → **음성(흥분도) + 언어(방향성)**.

### 3-9. 템플릿 — 고도(altitude)의 사다리
세 템플릿은 "같은 요약의 3가지 크기"가 아니라 **목적이 다른 고도**. 아래가 위를 먹인다(일일→주간→기간).

- **📅 일일** — *오늘을 닫고 내일의 씨앗* (로컬, 가벼움). 주제별 기록 + "처음 나온/또 나온 생각" + 에너지 스냅샷 + 내일로 잇는 질문 1개. 의사결정 아님.
- **📆 주간** — *패턴 발견 + 첫 결정 요청* (첫 진짜 종합, 클라우드 선택). 반복(진화/맴돎)+에너지 배지 + **"지속 후보" 뷰 + 결정 프롬프트 [지속][보류][접기]** ← 사람 결정 루프가 켜지는 곳.
- **🗓️ 기간** — *긴 호흡의 방향·지속* (결정 누적 위). 버틴 줄기 + 결정들의 흐름. v1은 *가벼운 형*(긴 구간 반복 + 결정 로그), 실행추적·냉각 붙으면 풍부해짐.
- **형식 = 서술글 + 행동 요소 둘 다.** "가공된 *글*"(AI가 문장으로 쓴 회고) + 지속 후보 카드·결정 버튼. 대시보드만이 아니라 *읽히는 글*.

### 3-10. v1 템플릿 범위
- **일일 + 주간은 v1에 온전히** (일일=습관, 주간=핵심 가치=통찰+결정).
- **기간은 v1엔 기본형**(긴 구간 반복 + 결정 로그), 후속에 풍부해짐.

### 3-11. 로컬 스택 — iOS 26+ Apple 온디바이스 올인
- **바닥: iOS 26+.** 거의 100% Apple 온디바이스 → 모델 번들 0, 최고 프라이버시 스토리, 유지보수·의존성 최소. (구형 기기 미지원 수용)
- **컴포넌트(1순위 / 교체 대안)**:

  | 필요 | 1순위(Apple) | 대안(품질 부족 시) |
  |------|-------------|-------------------|
  | STT | **SpeechTranscriber**(✅ 검증, 레거시 SFSpeechRecognizer 버림) | WhisperKit(CoreML Whisper) |
  | 로컬 LLM(태깅·일일정리) | **Foundation Models** ~3B | MLX + 소형 오픈모델 |
  | prosody | **Accelerate/vDSP** 직접 | — |
  | 임베딩(주제 통합) | **NLContextualEmbedding** | 다국어 sentence-transformer(CoreML) |

- **STT 결정**: Apple SpeechTranscriber로 시작, 한국어 품질 보고 **WhisperKit 교체 여지**.
- **로컬 LLM이 작아도 됨**: 깊은 종합은 클라우드로 뺐으니 로컬은 가벼운 일만 → 소형 모델의 강점 구간.
- **prosody = 해석 가능한 음향 특징**(음량·피치변동·말속도 → 각성도 점수). **블랙박스 감정 AI 아님.** 각성도(흥분)만, 방향(긍/부정)은 언어가 담당. **내 평소 대비 상대값**으로, 부드러운 신호.
- **관통 원칙 — 경계 추상화**(feedback-app storage.ts처럼): `Transcriber`/`LocalSynthesizer`/`ProsodyAnalyzer`/`Embedder` 인터페이스로 감싸 컴포넌트별 교체 가능.
- ⚠️ **구현 초기 스파이크 필요**: Apple API들의 **한국어 온디바이스 품질**을 직접 검증 후 1순위/대안 확정. (결과는 `docs/spike-findings.md`)
- ✅ **임베딩 검증됨**: NLContextualEmbedding 한국어 OK, 단 **중심화(anisotropy 보정) 전처리 필수**. sentence-transformer 번들 불필요.
- ✅ **STT 검증 완료**: SpeechTranscriber 한국어 on-device. **실기기 실음성 문자정확도 ~92.8%** → v1 확정, WhisperKit 불필요. (추임새 '음→응' 정도 사소 오류)
- 🛑 **Foundation Models 가드레일 리스크**: 무해한 교사·아동 문장 일부를 거짓 차단. **로컬 LLM은 "Apple FM + MLX 오픈모델 폴백" 이중화 필수**(가드레일 회피). 차단 시 우아한 폴백 설계. (MLX 폴백 PoC ✅ — spike-findings ④)

### 3-12. 클라우드 제공자 · 저장 (확정)
- **깊은 종합 클라우드 = Claude(Anthropic)**: 한국어 종합·추론 우수 + API 기본 비학습. `DeepSynthesizer` 인터페이스로 추상화(교체 가능). **증류층만, 옵트인 시에만** 전송.
- **로컬 주 저장 = SwiftData**: Capture/Theme/Digest/Decision + 임베딩(512d blob).
- **동기화 = 단일 기기 우선**(v1). iCloud는 옵트인 후속.
- **백업 = 사용자 주도 암호화 내보내기**(파일).
- **Obsidian 이중 저장(사용자 요구)**: 포착·정리를 **옵시디언 볼트에 마크다운으로 동시 미러링** → 사용자 소유·이식·그래프 활용. vibe-code 노트 철학과 동일.
  - 형식: frontmatter(날짜·에너지·봉인 등) + 본문. **주제 = `[[위키링크]]`** → Obsidian 그래프에 thought-thread 시각화.
  - 방향(제안): **단방향(앱→Obsidian)** v1. 양방향(역반영)은 충돌 처리 복잡 → 후속.
  - 봉인 처리(변경): **봉인 포착은 Obsidian '봉인' 폴더에 따로 미러**(일반은 Captures/). **클라우드 깊은 종합엔 여전히 제외**(Distillation에서 필터). 단 볼트가 iCloud 동기화되면 봉인도 기기를 떠남 → 사용자 선택·명시.
  - ⚠️ 프라이버시: 볼트가 iCloud 동기화되면 평문 기록이 기기를 떠남 → 사용자 선택이되 명시.

## 4. 데이터 모델 strawman (초안)

```
Capture(포착)   : 원문(텍스트), 시각, 에너지점수(prosody), 감정방향?, 봉인여부, 주제후보태그[]
Theme(주제)     : 통합된 줄기(emergent+병합). Capture들이 모임. 상태(활성/맴돎/냉각/결정됨).
                  사용자 큐레이션(이름변경·합치기·나누기·고정) 가능.
Digest(가공글)  : 템플릿(일/주/기간), 기간, 서술글 + 행동요소, 생성위치(로컬/클라우드), 근거 Capture[]
Decision(결정)  : Theme에 대한 지속/보류/접기 + 이유 + 시각  (→ 다음 회고로 피드백)
```
- 향후 확장(실행·연결·냉각)은 자리만 남기고 지금 안 만든다(YAGNI).
- v1은 **Capture → 통합(Theme) → Digest(일/주)** 한 줄기를 관통하는 수직 슬라이스로 시작.

### 산출물 예시 — 주간/기간 정리 안의 "지속 후보" 뷰
```
🌱 "수업 회고를 글로 남기기"   진화↑ 에너지高        [지속][보류][접기]
🔁 "학부모 응대 스트레스"      맴돎 에너지高(부정) → '해소'가 필요  [지속][보류][접기]
❄️ "유튜브 채널 아이디어"      3주째 냉각(한때 뜨거움)  [되살리기][접기]   ← 냉각은 post-v1
```

## 6. 조심할 함정 (토론에서 나온 것)

- ⚠️ 반추(rumination) 함정: 높은 반복+에너지가 *불안*일 수도 → 진화/맴돎 구분 + 감정 방향까지.
- ⚠️ 자기충족 루프: 앱이 X를 자꾸 띄우면 X를 더 말하게 됨 → 조용해진 줄기도 균형 있게 노출.
- ⚠️ 클라우드가 가장 필요한 곳(깊은 종합)이 가장 사적인 곳 → 2단계 증류로 가름.
- ⚠️ 라벨 표류(같은 주제를 다르게 명명) → 통합(임베딩 병합) + 사용자 큐레이션으로 방지.
