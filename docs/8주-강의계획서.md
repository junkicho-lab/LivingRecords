## 과목 개요

| 항목 | 내용 |
|---|---|
| **대상** | Swift 기초 문법을 아는 학생(변수·함수·옵셔널·클로저 수준) |
| **선수지식** | Swift 기본. SwiftUI/SwiftData는 본 과목에서 다룸 |
| **개발 환경** | macOS + Xcode(iOS 26+ SDK), **실기기 1대 권장**(음성·위젯·알림은 실기기 필요) |
| **시간 배분** | 주당 **3시간**(① 이론·결정 1h → ② 코드 리딩 1h → ③ 실습/라이브코딩 1h) + 과제 |
| **수업 방식** | 단순 따라치기 ✗ — *"왜 그렇게 정했나"*를 먼저 묻고, 커밋 diff로 변화를 추적 |

### 학습 성과(이수 후 할 수 있는 것)
1. **수직 슬라이스**로 작동하는 앱을 단계별로 키운다.
2. 불확실한 기술을 **스파이크**로 검증한 뒤 설계한다.
3. AI(온디바이스 LLM·임베딩)를 **믿을 만큼만** 쓰고, 못 믿는 부분을 **결정적 규칙**으로 보완한다.
4. **프라이버시·데이터 소유권**을 코드로 강제한다.
5. 막히면 *범위를 좁히거나 되돌릴* 줄 안다(실패 처리).

### 평가 비중
| 항목 | 비중 | 설명 |
|---|---|---|
| 주간 실습/과제 | 30% | 매주 마일스톤 제출(코드+짧은 회고) |
| 스파이크 재현 리포트 | 15% | 임베딩·의도감지 스파이크 재현 + 해석 |
| 판단 분석 에세이 | 15% | 설계 결정 1건 분석("나라면?") |
| 프라이버시 감사 | 10% | 봉인이 기기를 떠날 모든 경로 추적 |
| 기말 프로젝트 | 30% | 자신만의 슬라이스/확장 + 발표 |

> **루브릭(공통):** 슬라이스가 *작동*하는가 · 검증 습관 · 판단의 근거 기록 · 프라이버시 경계 · 실패 처리.

# 주차별 상세

## 1주차 — 오리엔테이션 · 개발 방법론 · 구상과 검증

**학습 목표**
- 이 프로젝트로 *무엇을* 배우는지(코드가 아니라 판단의 흐름) 이해한다.
- 수직 슬라이스·스파이크 우선·"구현→검증→커밋" 규율을 안다.
- 스파이크를 직접 실행해 "불확실성을 사실로 바꾸는" 경험을 한다.

**강의 흐름**
1. *이론(1h):* 앱 비전("무엇을 지속할까") · 7대 방법론 원칙 · 왜 docs가 코드만큼 중요한가.
2. *코드 리딩(1h):* 저장소 구조 둘러보기 — `docs/` 먼저, 그다음 소스 지도. 커밋 1번(`a89972f`) 열어보기.
3. *실습(1h):* Xcode·실기기 셋업. `spike/embed_spike3.swift` 또는 `intention_spike2.swift`를 `swift`로 실행해 출력 재현.

**실습/과제**
- 환경 셋업 인증(빌드되는 빈 프로젝트 스크린샷).
- 스파이크 1개 실행 결과 + "이 결과가 설계에 어떻게 영향을 줄까" 3문장.

**읽기:** `프로젝트-보고서.md` §0~§2, `concept.md`(통독), `spike-findings.md` ①②③⑥.

**체크포인트:** "수직 슬라이스 한 줄 정의"를 자기 말로 적기.

## 2주차 — v1 기반: 포착 → 저장 → 목록 · 에너지 · 봉인

**학습 목표**
- SwiftData `@Model`/`@Query`로 *저장되고 화면에 뜨는* 최소 흐름을 만든다.
- 가장 중요한 흐름(포착)을 먼저 관통시키는 이유를 안다.
- prosody 점수만 남기고 오디오를 폐기하는 프라이버시 결정을 이해한다.

**강의 흐름**
1. *이론:* SwiftData 기초(모델·컨텍스트·쿼리·마이그레이션) · SwiftUI 상태(`@State`/`@Environment`).
2. *코드 리딩:* `Models.swift` → `CaptureView.swift` → `CaptureListView.swift`. 커밋 `12f89de`·`930cc73`.
3. *라이브코딩:* 텍스트 포착→저장→목록을 처음부터(녹음은 다음 단계로 좁혀도 됨).

**실습/과제 (마일스톤 1)**
- S0~S2 직접 구현: 텍스트(최소)·가능하면 음성 포착 + 에너지/봉인 필드.
- 회고 3문장: "포착을 먼저 만든 이유 / 막힌 점 / 좁혀서 해결한 법".

**읽기:** 보고서 단위 1-1~1-3, `v1-slices.md` S0~S2.

**체크포인트:** 봉인(sealed)이 *어떤 문제*를 푸는지 한 문장.

## 3주차 — v1 데이터: Obsidian 미러 · 분류·통합(주제) ⭐가장 어려운 주

**학습 목표**
- 앱 데이터를 사용자 소유 형식(마크다운)으로 **단방향** 내보낸다.
- 비슷한 포착을 주제로 묶을 때 *임베딩·FM의 한계*를 직접 만난다.
- "자동은 best-effort, 정리는 사람이"라는 핵심 설계를 체득한다.

**강의 흐름**
1. *이론:* security-scoped bookmark(샌드박스 밖 접근) · 임베딩과 코사인 유사도 · **중심화** · FM 가이드 생성(`@Generable`).
2. *코드 리딩:* `VaultStore`·`ObsidianMirroring` → `Embedding`·`ThemeAssigning`·`Consolidation`·`Curation`. 커밋 `e66c50f`·`0baf42d`·`24194a3`.
3. *실습:* 스파이크 `embed_spike3`·`binary_spike`를 돌려 *왜 임계값 군집화가 실패하고 FM 배정으로 갔는지* 재현.

**실습/과제 (마일스톤 2 + 스파이크 리포트 제출)**
- S3 미러 + S4 주제 묶기(불완전해도 OK) + 큐레이션 1종(이름변경 또는 합치기).
- **스파이크 재현 리포트(평가 15%):** 임베딩/의도감지 스파이크 결과 재현 + "왜 그 결론" 해석.

**읽기:** 보고서 단위 1-4·1-5, `spike-findings.md` ⑤⑥, `v1-slices.md` S3·S4.

- 비싼 작업(클라우드 요약)을 *명시적 액션*으로만 두는 설계를 본다.

**강의 흐름**

## 8주차 — 실패·점검에서 배우기 · 종합 발표

**학습 목표**
- *되돌릴 줄 아는 것*도 실력임을 양방향 Obsidian 철회 사례로 배운다.
- 한 기술의 한계(임베딩)를 반복적으로 만나면 *접근을 바꾸는* 판단을 안다.
- 프라이버시 불변식을 끝까지 감사한다.

**강의 흐름**
1. *이론:* 양방향 중복 생성 사고의 *근본 원인*과 안전장치 · 임베딩 한계 3회 · 막바지 코드 리뷰(봉인 클라우드 누수).
2. *코드 리딩(diff 비교):* `184c6a9`(양방향 도입) ↔ `59f559c`(철회) · `c8c36db`/`ab886ee`(관련 주제 튜닝→제거) · `232fa5a`(점검·누수 수정).
3. *발표:* 기말 프로젝트 발표.

**실습/과제 (기말)**
- **프라이버시 감사(평가 10%):** "봉인이 기기를 떠날 수 있는 모든 경로"를 코드에서 추적해 표로(힌트: 클라우드 vs 볼트 iCloud 동기화).
- **기말 프로젝트(평가 30%):** 자신만의 슬라이스/확장 + 발표(아래 D 중 택1 가능).

**읽기:** 보고서 페이즈 8, 메모/커밋 메시지(철회 사유).

**체크포인트:** "전체 다시 내보내기 먼저" 안내만으론 왜 부족했나.

## 운영 팁 (강사용)

- **실기기 1대**를 분반에 공유하거나, 음성·위젯·알림 단원은 시연 중심으로(시뮬레이터 한계 명시).
- 매주 **커밋 diff를 함께 읽기** — "무엇이 추가됐나"가 가장 좋은 교재.
- 따라치기보다 **"왜"를 먼저 묻기**: 각 단위 복습 질문을 토론 발문으로.
- 막히면 **범위를 좁히도록** 지도(예: "음성 말고 텍스트 포착만 먼저").
- 실패 사례(8주차)를 *부끄러운 것*이 아니라 *가장 값진 교재*로 다룬다.

## 분량 조정 안내

- **단기(4주) 압축:** W1(방법론+구상) → W2(v1 S0~S4) → W3(v1 정리·클라우드+v2 핵심) → W4(되살아남/위키 + 실패에서 배우기·발표).
