# 머리말

이 책은 한 iOS 앱 **"생동하는 기록(Living Record)"** 이 *구상 → 검증 → 67개 커밋*을 거쳐 완성되는 전 과정을, **하나씩 다시 공부할 수 있게** 묶은 통합 교재다.

겉보기엔 음성 메모 앱이지만, 이 책이 가르치는 것은 코드가 아니라 **판단의 흐름**이다 — 무엇을 자동화하고 무엇을 사람에게 남길지, 무엇을 믿고 무엇을 검증할지, 언제 밀고 언제 되돌릴지.

## 누구를 위한 책인가
- **학생** — SwiftUI/SwiftData를 배우며 *설계 사고*를 익히려는 사람.
- **강사** — 프로젝트 기반(PBL) 강의를 운영하려는 사람(8주 계획·루브릭·문제은행 포함).
- **독학자** — 실제 앱의 결정과 실패를 따라가며 혼자 공부하려는 사람.

> 선수지식: Swift 기본 문법(변수·함수·옵셔널·클로저). SwiftUI/SwiftData는 본문에서 다룬다.

## 이 책의 구성 (4부)

- **제1부 · 본문(학습 보고서)** — 9페이즈·25개 학습 단위로 전 과정을 해설. *이 책의 척추.*
- **제2부 · 설계 원자료** — 구상(결정 토론)·기술 검증(스파이크)·단계별 계획·완성본 사용법. *왜 그렇게 정했는지의 1차 사료.*
- **제3부 · 강의 운영(강사용)** — 8주 강의계획서·채점 루브릭·모범답안집.
- **제4부 · 학생 자료** — 워크북·문제은행·포트폴리오 템플릿.

> 발표용 **슬라이드(Marp)** 는 선형 책에 맞지 않아 별도 파일로 둔다: `주차별-슬라이드개요.md`(영문 `en/slides.md`). `marp` 또는 VS Code Marp 확장으로 PDF/PPT 변환.

| 목적 | 추천 경로 |
|---|---|
| **자습** | 1부(보고서)를 페이즈 0→8 순서로 + 각 단위의 원자료(2부) 교차 읽기 |

# 프로젝트 보고서 — "생동하는 기록(Living Record)" 앱 만들기

> 이 문서는 한 앱이 *구상 → 검증 → 67개 커밋*을 거쳐 완성되는 전 과정을, **하나씩 다시 공부할 수 있게** 정리한 보고서다.
> 같이 읽을 설계 문서: `concept.md`(결정 토론) · `spike-findings.md`(기술 검증) · `v1~v4-slices.md`(작업 계획) · `사용설명서.md`(완성본 사용법)

## 0. 이 프로젝트로 무엇을 배우나

겉보기엔 "음성 메모 앱"이지만, 학습의 진짜 목표는 **앱 하나가 만들어지는 사고의 흐름**이다.

**학습 목표**
1. **수직 슬라이스**로 기능을 쪼개 *작동하는 앱*을 한 단계씩 키우는 법.
2. **불확실한 기술은 코드 전에 스파이크(실험)로 검증**하는 습관.
3. AI(온디바이스 LLM·임베딩)를 **믿을 수 있는 만큼만** 쓰고, 못 믿는 부분은 **결정적 규칙**으로 보완하는 판단.
4. **프라이버시·데이터 소유권**을 처음부터 설계에 박는 법.
5. **실패에서 배우기** — 되돌린 기능, 버린 접근, 고친 버그가 이 프로젝트의 가장 값진 교재다.

**핵심 가치(앱이 답하려는 질문)**: *"나는 무엇을 지속할 것인가?"* — 흩어진 생각을 모아, 무엇을 이어가고 무엇을 놓을지 사람이 결정하도록 *증거*를 보여주는 앱.

## 1. 개발 방법론 (모든 단계에 관통하는 원칙)

이 프로젝트가 따른 작업 규율. **단계마다 똑같이 반복된다.**

| 원칙 | 뜻 | 어디서 드러나나 |
|---|---|---|
| **수직 슬라이스** | UI~저장까지 한 흐름을 관통하는 최소 단위로 작업 | S0~S15, 각 커밋이 *작동하는* 한 조각 |
| **스파이크 우선** | 불확실한 기술은 본 구현 전 작은 실험으로 검증 | `spike/` 24개, `spike-findings.md` |
| **구현 → 실행 검증 → 커밋** | 빌드만이 아니라 *실제로 돌려보고* 커밋 | 모든 feat 커밋 |
| **결정은 사람이** | AI는 증거 제시까지, 판단은 사용자 | 지속/보류/접기, 큐레이션 |
| **결정적인 건 결정적으로** | AI가 못 믿을 부분은 규칙으로 | 의도 어미 게이트, 날짜 창 |
| **프라이버시 우선** | 로컬 기본, 클라우드는 옵트인·증류층만, 봉인 | 2단계 증류, 봉인 폴더 |
| **문서로 결정을 남긴다** | 왜 그렇게 정했는지 토론·근거를 기록 | concept/spike/slices 문서 |

> **학습 포인트:** 좋은 코드보다 *좋은 판단의 기록*이 먼저다. 이 앱의 docs 폴더가 코드만큼 중요한 이유.

## 페이즈 0 — 구상과 검증 (코드 0줄)

### 단위 0-1. 무엇을·왜 만드나 (구상)
- **목표:** 막연한 아이디어를 *결정된 사항*과 *미결*로 가르기.
- **핵심 개념:** 차별점 정의("무엇을 지속할까"), 프라이버시 하이브리드, 2단계 증류, 분류=주제(emergent+통합).

- **배울 점:** 코드 전에 *토론으로 결정을 고정*한다. 바뀌면 문서를 갱신한다.
- **복습 질문:** 이 앱이 "음성 메모 + AI 요약"과 다른 단 하나는? 봉인(sealed)은 어떤 문제를 푸는가?

### 단위 0-2. 스파이크 — 하드 파트 먼저 검증
- **목표:** "Apple 온디바이스 AI가 *한국어로* 쓸 만한가?"를 본 구현 전에 실측.
- **핵심 개념:** 스파이크(throwaway 실험), 가설→측정→판정.
- **읽을 것:** `spike-findings.md` ①~⑧, `spike/` 폴더(24개).
- **핵심 발견:**
  - ① 임베딩: 한국어 OK, **단 중심화 전처리 필수**(안 하면 다 몰림).
  - ② STT: 신형 **SpeechTranscriber** 확정(레거시 버림). 실음성 문자정확도 92.8%.
  - ③ FM 가드레일: 무해한 교사·아동 문장도 거짓 차단 → 폴백 필요.
  - ⑥ 주제 자동분류: 온디바이스 FM 불안정(과병합↔과분할) → **best-effort + 큐레이션**.
- **배울 점:** *불확실하면 작게 실험해 사실을 손에 쥔 뒤 설계한다.* 스파이크는 버리는 코드라 빨리 쓴다.
- **복습 질문:** 중심화(centering)는 왜 필요했나? FM을 못 믿는다는 걸 어떻게 *측정*했나?

- **핵심 개념:** security-scoped bookmark(샌드박스 밖 폴더 접근), frontmatter+위키링크.

### 단위 1-5. S4 분류·통합(주제) — *가장 어려운 단위*

- **핵심 개념:** emergent 태깅 vs 임베딩 군집화 vs **FM 의미 배정**, 라벨 표류.
- **파일:** `Consolidation.swift`, `ThemeAssigning.swift`, `ThemeNaming.swift`, `Embedding.swift`, `Curation.swift`, `ThemeListView.swift`.
- **커밋:** `0baf42d`, `24194a3`, `8f6aea5`.
- **배울 점(중요):** 스파이크 ⑥에서 *임베딩 임계값 군집화 실패 → FM 배정 → 그래도 기기서 불안정* → **결론: 자동은 best-effort, 정리는 사람이.** 완벽한 자동화를 포기하고 *교정 가능한 설계*로.
- **복습 질문:** 임베딩 유사도 순위가 왜 못 믿을까? "과분할이 과병합보다 안전"한 이유는?

```
   │ text, createdAt, energy?, sealed,        │ name, state, summary?(위키)
   │ embedding(512d)?, sortIndex               └ Commitment(다짐): themeID 스냅샷
   └ 봉인이면 클라우드·갤러리 제외

Digest(정리: 일/주/기간)   Transmission(클라우드 전송 로그)   CustomTemplate(사용자 템플릿)
```
> SwiftData **경량 마이그레이션**: 필드 추가/모델 추가는 자동(Commitment·CustomTemplate·summary·mirrored 등 그렇게 들어옴).

## 0. 한 줄 정의

> **말로 쏟아낸 생각을 로컬에 모아두면, AI가 분석·분류·정리해 '가공된 글'(일/주/기간 템플릿)로 만들고, 결국 "내가 무엇을 지속할 것인가"를 돕는 앱.**

## 1. 핵심 루프

```
포착(말) → 저장(텍스트, 로컬) → AI 분석·분류 → 가공(템플릿: 일/주/기간) → 회고·결정(무엇을 지속?)
                                                                    ↘ 결정이 다음 회고로 피드백
```

## 2. 차별점 / 해자

- 흔한 "음성 메모 + AI 요약"과 다른 한 가지: **"앞으로 무엇을 지속할 것인가"를 돕는다.**
- 진짜 해자: **음성**이라서 *목소리의 결(에너지)*을 읽을 수 있다 — 텍스트 일기 앱은 못 하는 것.
- 기계는 **판결하지 않는다.** 증거를 제시 → **사람이 결정** → 그 결정이 데이터가 되어 다음을 똑똑하게.

---

## 3. 결정된 사항 ✅

### 3-1. 프라이버시: 하이브리드
- **포착·저장은 로컬**, **가공만 선택적으로 클라우드**.
- 원칙: **클라우드를 한 번도 안 켜도 앱은 쓸모 있어야 한다**(클라우드는 의존이 아니라 업그레이드).
  - 로컬 담당: 포착(STT) + 저장 + 분류/태깅/통합 + **일일 가벼운 정리**
  - 클라우드 담당: 주간·기간의 **깊은 종합**(추세·반복·연결·지속 제안)

### 3-2. 2단계 증류 (원문은 로컬 봉인)
```
[로컬] 원문(verbatim) ──로컬 LLM──▶ 증류층(주제·요약·키워드)
                                       └─(켤 때만)──▶ [클라우드] 깊은 종합
```
- **날것의 말(원문)은 절대 기기를 떠나지 않는다.** 클라우드로 가는 건 로컬이 추상화한 *증류층*뿐.

### 3-3. 클라우드 동의 모델: "한 번 켜기 / 봉인 예외 / 사후 열람" (매번 묻지 않음)
1. **한 번 설정** — "깊은 종합은 클라우드 허용" 스위치(기본 OFF, 켜는 건 의식적으로 한 번).
2. **봉인(예외)** — 포착할 때 *진짜 사적*이면 그 자리에서 **봉인**. 봉인된 포착·주제는 전역 스위치가 켜져도 클라우드로 안 감. (포착 트리거에 흡수 — 아래 3-4)
3. **전송 로그** — "언제 무엇이 클라우드로 나갔나"를 언제든 볼 수 있게(사전 차단 대신 사후 감사).

### 3-4. 포착 (Capture) — 마찰 0
- **원칙: 포착 = 한 동작, 결정 0개.** 말하고 끝. 분류·태깅·정리는 전부 나중에 AI가.
  - 포착 화면 = 녹음 버튼 + 텍스트칸 + 끝. **분류 UI 없음.**
- **주 기기: 폰(이동 중) 1순위** → 모바일 우선. **플랫폼: iOS 우선**(Android 나중).
- **트리거(v1): 홈/잠금화면 위젯 한 탭**. 액션버튼·AirPods 꾹은 *나중 업그레이드*.
  - ~~항상 듣기~~ 탈락 — 프라이버시 + 포착은 *의도적* 행위.
  - **봉인 = 트리거에 흡수**: 탭=일반 / 꾹누르기=봉인 (둘 다 한 제스처). 봉인은 사후 로그에서도 가능.
- **말한 직후**: 즉시 저장(fire-and-forget). STT·prosody·오디오 폐기는 **백그라운드**. 확인은 조용한 신호(진동 등).
- **텍스트 폴백**: 음성 우선, 텍스트는 항상 가능(회의·공공장소 대비).

### 3-5. 분류 체계 — emergent + 통합
- **여기서 분류 = "폴더에 넣기"가 아니라 "주제(Theme)로 묶기"** = 반복 신호의 토대.
- 고정 틀 ✗ (생각 범주를 미리 예측 못 함 + 발견을 죽임 + 포착 마찰). 순수 emergent도 ✗ (라벨 표류로 반복 카운트 깨짐).
- **답: AI가 자유롭게 주제 부여 → 임베딩 유사도로 비슷한 것 병합해 안정된 Theme.** 아래에서 자라는 + 자기 병합. **로컬에서**.
- **축은 하나(주제)**. 유형/감정 결은 신호(맴돎/진화/에너지)가 담당.
- **사용자 큐레이션 v1 포함**: 주제 이름변경·합치기·나누기·고정. (AI 통합 불완전 + 반복 정확도가 주제 경계에 달림). 교정도 피드백 데이터.

### 3-6. "지속할 것"을 알아채는 신호 (전체 5개)
1. **반복** — *진화하는 반복*(말할수록 생각이 자람=살아있음) vs *맴도는 반복*(같은 말 되풀이=교착·걱정). **이 구분이 앱의 지능.**
2. **에너지** — 목소리의 결로 읽는 흥분/몰입 (해자).
3. **실행 추적** — "하겠다"가 나중에 살아남았는가.
4. **연결** — 멀리 떨어진 생각이 한 줄기로 모이는 순간(영감).
5. **냉각** — 뜨거웠다 식은 주제. *접을 것*도 알아채야 함(지속 = 이어가기 + 가지치기).

### 3-7. v1 신호 범위
- **v1: 반복(진화/맴돎) + 에너지** 만. (데이터가 적어도 바로 작동)
- 다음 단계: 실행 추적 · 연결 · 냉각 (쌓여야 의미 생김).

### 3-8. 에너지 출처: 절충안 C (포착 순간 점수만, 오디오 폐기)
```
말함 → [포착 순간, 로컬]
        ├─ STT로 텍스트 추출 ──────────▶ 저장
        ├─ prosody 요약치(에너지 점수 1~2개) 추출 ─▶ 저장
        └─ 오디오 원본 즉시 폐기 ✗
```
- 목소리 기반 에너지(해자)는 **확보**, 가장 민감한 오디오는 **안 쌓음**(프라이버시 유지), 용량 부담 없음.
- 언어 기반 신호(긍/부정 방향)는 텍스트에서 얹음 → **음성(흥분도) + 언어(방향성)**.

### 3-9. 템플릿 — 고도(altitude)의 사다리
세 템플릿은 "같은 요약의 3가지 크기"가 아니라 **목적이 다른 고도**. 아래가 위를 먹인다(일일→주간→기간).

- **📅 일일** — *오늘을 닫고 내일의 씨앗* (로컬, 가벼움). 주제별 기록 + "처음 나온/또 나온 생각" + 에너지 스냅샷 + 내일로 잇는 질문 1개. 의사결정 아님.
- **📆 주간** — *패턴 발견 + 첫 결정 요청* (첫 진짜 종합, 클라우드 선택). 반복(진화/맴돎)+에너지 배지 + **"지속 후보" 뷰 + 결정 프롬프트 [지속][보류][접기]** ← 사람 결정 루프가 켜지는 곳.
- **🗓️ 기간** — *긴 호흡의 방향·지속* (결정 누적 위). 버틴 줄기 + 결정들의 흐름. v1은 *가벼운 형*(긴 구간 반복 + 결정 로그), 실행추적·냉각 붙으면 풍부해짐.
- **형식 = 서술글 + 행동 요소 둘 다.** "가공된 *글*"(AI가 문장으로 쓴 회고) + 지속 후보 카드·결정 버튼. 대시보드만이 아니라 *읽히는 글*.

### 3-10. v1 템플릿 범위
- **일일 + 주간은 v1에 온전히** (일일=습관, 주간=핵심 가치=통찰+결정).
- **기간은 v1엔 기본형**(긴 구간 반복 + 결정 로그), 후속에 풍부해짐.

### 3-11. 로컬 스택 — iOS 26+ Apple 온디바이스 올인
- **바닥: iOS 26+.** 거의 100% Apple 온디바이스 → 모델 번들 0, 최고 프라이버시 스토리, 유지보수·의존성 최소. (구형 기기 미지원 수용)
- **컴포넌트(1순위 / 교체 대안)**:

  | 필요 | 1순위(Apple) | 대안(품질 부족 시) |
  |------|-------------|-------------------|
  | STT | **SpeechTranscriber**(✅ 검증, 레거시 SFSpeechRecognizer 버림) | WhisperKit(CoreML Whisper) |
  | 로컬 LLM(태깅·일일정리) | **Foundation Models** ~3B | MLX + 소형 오픈모델 |
  | prosody | **Accelerate/vDSP** 직접 | — |
  | 임베딩(주제 통합) | **NLContextualEmbedding** | 다국어 sentence-transformer(CoreML) |

- **STT 결정**: Apple SpeechTranscriber로 시작, 한국어 품질 보고 **WhisperKit 교체 여지**.
- **로컬 LLM이 작아도 됨**: 깊은 종합은 클라우드로 뺐으니 로컬은 가벼운 일만 → 소형 모델의 강점 구간.
- **prosody = 해석 가능한 음향 특징**(음량·피치변동·말속도 → 각성도 점수). **블랙박스 감정 AI 아님.** 각성도(흥분)만, 방향(긍/부정)은 언어가 담당. **내 평소 대비 상대값**으로, 부드러운 신호.
- **관통 원칙 — 경계 추상화**(feedback-app storage.ts처럼): `Transcriber`/`LocalSynthesizer`/`ProsodyAnalyzer`/`Embedder` 인터페이스로 감싸 컴포넌트별 교체 가능.
- ⚠️ **구현 초기 스파이크 필요**: Apple API들의 **한국어 온디바이스 품질**을 직접 검증 후 1순위/대안 확정. (결과는 `docs/spike-findings.md`)
- ✅ **임베딩 검증됨**: NLContextualEmbedding 한국어 OK, 단 **중심화(anisotropy 보정) 전처리 필수**. sentence-transformer 번들 불필요.
- ✅ **STT 검증 완료**: SpeechTranscriber 한국어 on-device. **실기기 실음성 문자정확도 ~92.8%** → v1 확정, WhisperKit 불필요. (추임새 '음→응' 정도 사소 오류)
- 🛑 **Foundation Models 가드레일 리스크**: 무해한 교사·아동 문장 일부를 거짓 차단. **로컬 LLM은 "Apple FM + MLX 오픈모델 폴백" 이중화 필수**(가드레일 회피). 차단 시 우아한 폴백 설계. (MLX 폴백 PoC ✅ — spike-findings ④)

### 3-12. 클라우드 제공자 · 저장 (확정)
- **깊은 종합 클라우드 = Claude(Anthropic)**: 한국어 종합·추론 우수 + API 기본 비학습. `DeepSynthesizer` 인터페이스로 추상화(교체 가능). **증류층만, 옵트인 시에만** 전송.
- **로컬 주 저장 = SwiftData**: Capture/Theme/Digest/Decision + 임베딩(512d blob).
- **동기화 = 단일 기기 우선**(v1). iCloud는 옵트인 후속.
- **백업 = 사용자 주도 암호화 내보내기**(파일).
- **Obsidian 이중 저장(사용자 요구)**: 포착·정리를 **옵시디언 볼트에 마크다운으로 동시 미러링** → 사용자 소유·이식·그래프 활용. vibe-code 노트 철학과 동일.
  - 형식: frontmatter(날짜·에너지·봉인 등) + 본문. **주제 = `[[위키링크]]`** → Obsidian 그래프에 thought-thread 시각화.
  - 방향(제안): **단방향(앱→Obsidian)** v1. 양방향(역반영)은 충돌 처리 복잡 → 후속.
  - 봉인 처리(변경): **봉인 포착은 Obsidian '봉인' 폴더에 따로 미러**(일반은 Captures/). **클라우드 깊은 종합엔 여전히 제외**(Distillation에서 필터). 단 볼트가 iCloud 동기화되면 봉인도 기기를 떠남 → 사용자 선택·명시.
  - ⚠️ 프라이버시: 볼트가 iCloud 동기화되면 평문 기록이 기기를 떠남 → 사용자 선택이되 명시.

```
Capture(포착)   : 원문(텍스트), 시각, 에너지점수(prosody), 감정방향?, 봉인여부, 주제후보태그[]

Digest(가공글)  : 템플릿(일/주/기간), 기간, 서술글 + 행동요소, 생성위치(로컬/클라우드), 근거 Capture[]
```

# 스파이크 결과 — 한국어 온디바이스 품질 검증

> 환경: macOS 26.6, Xcode 26.5, Swift 6.3.2 (맥에서 CLI 직접 실행)
> 목적: concept.md §3-11 로컬 스택의 Apple 온디바이스 1순위가 *한국어로* 쓸 만한지 실측.
> 스파이크 코드: `spike/` (embed_spike*.swift 등)

## ① 임베딩 (주제 통합) — ✅ 통과 (조건부)

- `NLEmbedding.wordEmbedding(for: .korean)` → **nil (한국어 word 임베딩 OS에 없음).**
- `NLContextualEmbedding(language: .korean)` → **로드 성공.** assets 이미 설치됨(다운로드 불필요), 512차원.
- 평균 풀링한 원본 코사인은 0.61~0.78로 **다 몰림(anisotropy)** → 같은/다른 주제 분리도 0.103, 순위 뒤엉킴.
- **중심화(전체 centroid 빼고 재정규화)** 적용 시 분리도 **0.380** → 군집 명확.

**판정:** Apple 온디바이스 한국어 임베딩으로 주제 통합 **가능. 단 중심화(anisotropy 보정) 전처리 필수.**
→ v1에서 다국어 sentence-transformer **번들 불필요**. Apple 네이티브 채택.

**적용 메모(구현 시):**
- 문장 벡터 = 토큰 벡터 평균 풀링 → **centroid 차감 + L2 정규화** 후 코사인.
- centroid는 충분한 배경 코퍼스(누적 포착)로 추정할수록 안정적. 초기엔 작은 표본이라 임계값 보수적으로.
- 주제 병합 임계값은 실데이터로 튜닝 필요.

## ② STT (한국어 받아쓰기) — 🟡 부분 (아키텍처 OK, 품질 미측정)

- `SFSpeechRecognizer(locale: ko-KR)` 생성 OK. CLI에서 **권한 통과**(raw=3).
- ⭐ **`supportsOnDeviceRecognition == true`** — 한국어 **on-device 지원 확인**(로컬 우선 설계 핵심).
- 그러나 `recognitionTask`가 헤드리스 CLI에서 **결과 콜백을 전혀 안 냄**(aiff·wav 모두, 55s 대기, 에러도 없음).
  - 원인 추정: on-device 모델 프로비저닝 미완 + `requiresOnDeviceRecognition=true` 무응답, 또는 앱 런루프/번들 컨텍스트 필요.
- 테스트 자산: `spike/cap.aiff`, `cap.wav` (say -v Yuna 합성, 7.5s).

### ②-new 신형 SpeechTranscriber/SpeechAnalyzer — ✅ 통과 (CLI에서도 작동)
- `SpeechTranscriber`/`SpeechAnalyzer`/`AssetInventory` 심볼 존재. ko-KR **supported=true, installed=true**, 에셋 자동 설치 OK.
- `analyzer.analyzeSequence(from: AVAudioFile)` + `transcriber.results`로 파일 전사 성공(헤드리스 CLI에서도).
- 결과: 단어 **100% 정확**(차이는 쉼표 1개), 문자 정확도 **97.7%** (cap.wav, TTS 합성).
- **판정:** 신형 SpeechTranscriber로 한국어 on-device STT **확정 채택**. 레거시 SFSpeechRecognizer는 버림.
- ⚠️ 단서: TTS 합성 음성 기준. 실제 사람 음성은 더 어려움 → 실기기 측정함(아래).

### ②-real 실기기 실음성 측정 — ✅ SpeechTranscriber 확정
- 앱 내 측정 도구(STTAccuracyView)로 실기기에서 6문장 자연 발화 → **평균 문자 정확도 92.8%**(공백 제외 CER 기준).
- 오류 예: 추임새 '음'→'응'(사소, 추임새는 노이즈에 가까움). 포착은 편집 가능 + 요지 중심이라 92.8%면 충분.
- **판정: SpeechTranscriber로 v1 확정. WhisperKit 불필요**(더 높은 정확도 필요 시에만 §3-11 대안).

## ③ Foundation Models (한국어 태깅·요약) — 🟡 작동하나 가드레일 리스크 (중요)

- `SystemLanguageModel.default.availability == .available`. CLI에서 **작동**.
- 한국어 태깅·요약 **품질 양호**(중립·학생·아이들 문장 대부분 그럴듯한 태그+요약 생성).
- 🛑 **그러나 가드레일 거짓 양성**: 무해한 교사 문장 일부가 `guardrailViolation("May contain unsafe content")`로 차단.
  - 차단: "오늘 수업에서 아이들이 발표할 때 눈빛이 살아있는 걸 보고, 이 방식을 계속 밀고 가야겠다…"
  - 통과: "우리 반 아이들이 글쓰기를 어려워해서…", "학생들과 텃밭을…", 중립 문장.
  - → "아이들" 자체가 아니라 **특정 표현 조합을 맥락 없이 오해**. 예측 불가·변덕스러움.
- **판정 / 설계 영향(중요):** 교사용 사적 회고 앱에서 **무해한 포착의 간헐적 침묵 거부 = 신뢰 붕괴 리스크.**
  - Foundation Models는 **단독 의존 금지.** §3-11 **MLX 오픈모델 대안이 (품질 아닌) 가드레일 회피용으로 필요**.
  - 또는: 차단 시 **우아한 폴백**(대체 모델 재시도 / 사용자 수동 태깅 / 자리표시). Apple 가드레일은 사용자가 끌 수 없음.
  - 클라우드 깊은 종합도 가드레일 있으나, 2단계 증류(추상화 전송)가 오탐을 줄일 여지.

## ④ MLX 오픈모델 폴백 PoC — ✅ 통과

- 머신에 ollama/llama.cpp/mlx_lm **없었음** → `pip install mlx-lm`(0.31.3)로 설치, Qwen2.5-1.5B-Instruct-4bit 사용.
- **FM이 차단했던 바로 그 문장**("…아이들이 발표할 때 눈빛이 살아있는…")을 정상 처리:
  태그=학문·발표, 요약=합리적. 가드레일 없음.
- 성능: 온디바이스 ~100 tok/s, **peak 1.0GB**. 1.5B는 한국어 태깅 "쓸 만함"(학문 태그는 부정확).
- **판정:** FM 가드레일 차단 시 **MLX 오픈모델 폴백 실현 가능**(완전 온디바이스). 품질 더 원하면 3B급 검토.
- 실제 앱은 mlx-swift(Swift)로 번들. (PoC는 python mlx-lm으로 빠르게 확인)

## ⑤ 임베딩 통합(군집화) PoC — ✅ 통과

- 중심화한 한국어 임베딩 + 온라인 그리디 군집화(임계값 기반).
- **임계값 −0.10 ~ 0.0 구간 → 정확히 3개 순수 클러스터**(수업/음식/운동). 너무 낮으면 섞임(잘못된 병합), 높으면 과분할.
- **판정:** 통합 알고리즘 유효. 기본 임계값 ~0.0, **보수적(순수) 군집화**로 잘못된 병합 회피 → 과분할은 '합치기' 큐레이션으로 해결.
- 핵심: 통합은 **임베딩만으로** 가능(LLM 불필요). LLM은 주제 *이름짓기*에만.
- spike: `cluster_spike.swift`.

## ⑥ 주제 배정: 임베딩 임계값 ❌ → FM 의미 배정 ✅ (중요 전환)

- **임베딩 임계값은 근본적으로 실패**: 합쳐야 할 쌍(수업1·2=0.209) < 합치면 안 될 쌍(등산·음식=0.353).
  유사도 순서가 어긋나 **어떤 단일 임계값으로도 둘 다 만족 불가**. 평균 풀링 NLContextualEmbedding이 다양한 한국어 주제 구분엔 너무 거침.
- **FM 구조화 출력(guided generation)로 배정 → 6/6 정확**: 깨끗한 주제명 목록 + `@Generable`로 번호(또는 -1) 강제.
  등산→새주제, 파스타→음식, 학부모상담·체육대회→수업 모두 정확.
- spike: `online_spike`(임계값 실패 재현), `fm_guided_spike`(6/6, macOS).

### ⑥-b 기기 검증: 온디바이스 FM 분류는 불안정 → best-effort + 큐레이션으로 확정
- **index 선택**(없으면 -1): 기기 FM이 주제 1개일 때 **전부 idx=0으로 쏠림**(유효 번호 선호 편향) → 과병합(전부 한 주제).
- **Bool "같은 분야?"**로 교체: 기기에서 이번엔 **과분할**("수업 끝나고 다시 생각"이 "수업"에 안 붙고 새 주제). macOS 스파이크(5/6)와 기기 동작이 **다름**.
- **결론(중요):** 온디바이스 FM의 짧은 한국어 자동 군집은 과병합↔과분할을 오가고 **환경마다 달라 프롬프트로 100% 불가**. 기기 접근 없이 튜닝 불가.
- **최종 설계(방안 A):** 자동 분류는 **보수적 best-effort**(Bool 판단, 과분할이 과병합보다 안전 — 합치기로 정리 가능) + **강한 큐레이션**(이름변경·합치기·포착 이동/추출). 자동은 출발점, 정리는 사용자가 2탭으로.
- 향후 개선 여지: 임베딩 top-K 후보 축소, 배치 "정리 제안"(FM이 합치기 제안→사용자 승인), 실기기 프롬프트 튜닝.

## ⑦ (v2 S8) 자동 의도 감지: FM ❌ → 의도 어미 결정적 게이트 ✅

- 같은 10문장(의도 5/관찰·감정 5)에 세 전략 비교:
  - **A(FM `@Generable` Bool만)**: 실행마다 출렁, 한 번은 6/10·다음 실행 1/10. 관찰을 의도로 과감지하다가, 명백한 의도("해봐야겠다")를 false로 떨구기도 — **양방향으로 불안정**(⑥-b의 yes 쏠림과 동류).
  - **B(한국어 의도 어미 결정적 게이트만)**: **10/10.** 마커=`겠/해야/하자/해보자/볼까/봐야지/야지/려고/을래·를래/시작하/다짐` 등 substring.
  - **C(게이트 AND FM)**: 6/10 — 완벽한 게이트를 FM이 끌어내림.
- **판정:** **의도 판정/감지는 결정적 어미 게이트**, FM은 *의도구(라벨) 추출에만* best-effort(실패·빈값 시 포착 텍스트 폴백). 가드레일·지연·번들 0. v1 ⑥-b 교훈("결정적으로 가능한 건 결정적으로, FM은 보조") 재확인.
- ⚠️ 단서: 손으로 고른 10문장 기준. 어미 게이트는 드물게 과발화 가능("좋겠다"=소망) — 보수적 허용(사용자가 무시 가능, FM 혼돈보다 안전). 마커셋은 실데이터로 정련.
- spike: `intention_spike.swift`(FM 단독), `intention_spike2.swift`(A/B/C 비교).

## ⑧ (v4 검색) 의미 검색 품질: 거침 → 하이브리드에서 '보조'로

- 코퍼스 12개(6주제)에 질문 6개 중심화 코사인 랭킹: **top-1 3/6, top-3 5/6**.
- 잘 맞음: "사람들과의 관계"→관계(0.47), "꾸준히 글 쓰기"→글쓰기(0.35). 빗나감: "건강을 위해 운동하기"→글쓰기(top), "돈 관리"→수업(top). ⑥(유사도 순서 어긋남)과 동일 한계.
- **판정:** 의미 검색을 정밀 랭킹으로 신뢰 불가 → **하이브리드 확정**: 전문(정확 포함)=주력·신뢰, 의미="비슷한 기록(추정)" 보조. 노이즈 컷 위해 유사도 임계값(~0.30)+상위 소수만, '추정' 라벨.
- spike: `search_spike.swift`.

## 종합 결론
- 임베딩 ✅(중심화 필수) · STT ✅(신형 SpeechTranscriber, 깨끗한 음성 97.7%) · FM 🟡(작동하나 가드레일 폴백 필요) · MLX 폴백 ✅(가드레일 없음).
- **로컬 스택 검증 완료**: STT=SpeechTranscriber 확정, 임베딩=NLContextualEmbedding+중심화, 로컬 LLM="Apple FM + MLX 폴백" 이중화.
- 남은 검증: 실제 사람 음성 WER(실사용 녹음), 폴백 모델 크기(1.5B vs 3B) 튜닝.

### S0 · 스캐폴딩

### S1 · 포착 → 저장 → 목록  ⭐핵심(마찰 0)

- **포함**: 포착 화면(녹음+텍스트칸, **분류 UI 없음**), 백그라운드 전사(fire-and-forget), 목록.
- **검증**: 한국어 발화 → 텍스트 저장·표시. 앱 죽여도 영속. (실제 사람 음성 WER 첫 측정)

- **목표**: 포착 순간 prosody 에너지 점수(vDSP) 추출 + **오디오 폐기**(절충안 C). 봉인(꾹 누르기) 포착.

### S3 · Obsidian 미러
- **목표**: 포착을 옵시디언 볼트에 마크다운으로 **단방향 미러**. frontmatter+본문. **봉인 제외**.
- **포함**: ObsidianMirror 구현, 볼트 폴더 선택(security-scoped bookmark), 파일명·폴더 규칙.
- **검증**: 포착 시 .md 생성, Obsidian에서 열림. 봉인은 미러 안 됨.
- **의존**: S1(+S2 봉인). 

### S4 · 분류·통합 (Theme)
- **목표**: emergent 태깅 + 임베딩 통합으로 Capture를 Theme으로 묶기. 큐레이션(이름변경·합치기·나누기).
- **포함**: LocalSynthesizer(Foundation Models + **MLX 폴백**: 가드레일 차단 시), Embedder(NLContextualEmbedding **+ 중심화**), 유사도 병합·임계값, Theme 화면, Obsidian 주제=`[[위키링크]]`.

- **의존**: S1. **스파이크 재사용**: `embed_spike3.swift`(중심화), `fm_spike2.swift`+`mlx`(폴백).

- **의존**: S4.

# 생동하는 기록 — v2 수직 슬라이스 계획 (지속 루프 완성)

> 작성: 2026-06-04 · 근거: `concept.md`(§1 핵심 루프, §3-6 신호 5개), `사용설명서.md`(v1 현황)
> 플랫폼: iOS 26+ · 워크플로: v1과 동일(구현 → 실기기 실행 검증 → 커밋, 슬라이스 태그 `feat(S8): …`)

## 0. v2의 목표 — 끊긴 화살표 잇기

concept §1의 핵심 루프에서 v1이 못 닫은 고리:

```
포착 → 주제 → [신호] → 결정 → ❳실행❲ → 다음 회고에 "그래서 어떻게 됐나"  ← v2가 채움
              └ v1: 반복·에너지·진화        ↑___________피드백___________↓
                v2: + 실행추적·냉각·연결
```

**v1 신호(3): 반복 · 에너지 · 진화/맴돎.** (+ 모멘텀·에너지추세는 직전 고도화로 추가)
**v2 신호(3): 실행 추적 · 냉각 · 연결** → concept §3-6의 5개 신호 완비 + 결정→실천→피드백 폐곡선.

## 1. 굳은 결정 (이 v2 계획의 전제)

- **실행 추적 = "자동 의도 감지".** 이 앱은 실제 행동을 못 본다 → "말 속의 *의도*가 이후 살아남았는가"로 정의(concept §3-6.3 그대로). 포착 마찰 0 유지(사용자가 표시 안 함, 로컬 AI가 감지).
- **범위 = S8→S9→S10→S11 순차.** 앞이 실기기에서 돌면 다음으로.
- **모든 신호는 로컬.** 의도 감지·냉각·연결 계산 전부 온디바이스(FM/임베딩/NLTagger). 클라우드는 기존처럼 주간·기간 깊은 종합에서만(증류층, 옵트인, 봉인 제외).
- **자기충족 루프 방지(concept §6).** 시끄러운 것만 키우지 않게, 조용해진 줄기·냉각도 균형 노출.
- **데이터 모델은 자리만 → 이제 채움.** v1의 `Decision`은 그대로, 실행 추적용 `Commitment` 신설(additive → SwiftData 경량 마이그레이션).

## 2. 슬라이스

### S8 · 실행 추적 (의도의 생존) ⭐ 루프의 심장
- **목표**: 포착 속 의도·다짐을 로컬에서 감지해 **약속(Commitment)** 으로 남기고, 이후 **살아남았는지/흐지부지됐는지** 추적해 회고에 보여준다.
- **포함**:
  - `IntentionDetector` 인터페이스 + FM 구현: `@Generable { hasIntention: Bool, phrase: String }` — "이 메모에 앞으로 하겠다는 의도/계획/다짐이 있나? 있으면 핵심 의도구만 추출." 가드레일/불가 시 폴백(감지 안 함, 보수적).
  - 통합(`Consolidator.consolidate`) 끝에 의도 감지 → 있으면 `Commitment(text: phrase, sourceCapture, theme, createdAt)` 생성.
  - **생존 판정(결정적)**: 약속 생성 이후 같은 주제에 새 포착이 있으면 `surviving`, 일정 기간(예: 10일) 활동 0이면 `faded`. (의미 재언급까지는 후속 — 일단 활동 기반 보수적 신호)
  - 주간 회고에 **"이번 주 다짐"** 섹션: 살아남은 의도 / 잠잠해진 의도. Obsidian 미러에도 반영.
- **데이터**: 새 `@Model Commitment`(id, text, createdAt, statusRaw, lastActivityAt, sourceCapture?, theme?). `modelContainer`에 등록.
- **검증**: "다음 주엔 ~해봐야지" 류 발화 → 약속 생성. 같은 주제 후속 포착 → surviving. 방치 → faded. 의도 없는 메모는 약속 안 생김(과감지 적음).
- **의존**: v1 전체. **스파이크 권장**: 한국어 의도 감지 정밀도(FM @Generable) 짧게.

### S9 · 냉각 능동화 (가지치기 신호)
- **목표**: 뜨거웠다 식은 주제를 능동적으로 띄워 **되살릴지/놓을지** 묻는다. (지속 = 이어가기 + 가지치기)
- **포함**:
  - 냉각 판정: 이전엔 활발(예: 직전 2주 일정 임계↑)했는데 최근 창에서 모멘텀 강한 음수 → `Theme.state = .cooling`. (직전 모멘텀 계산 재사용·확장)
  - 주간 회고에 **❄️ "식어가는 줄기"** 섹션(지속 후보와 분리): `[되살리기][접기]`. concept §4 예시 그대로.
    - `[되살리기]` → state 복귀(active) + (선택) 내일 이어볼 질문 제안. `[접기]` → `Decision(.drop)`.
  - 균형 노출: "한동안 조용한, 한때 소중했던 주제" 1~2개를 부드럽게 환기(자기충족 루프 방지).
- **데이터**: 기존 `ThemeState.cooling` 활용(모델 변경 없음).
- **검증**: 한때 잦다 끊긴 주제가 ❄️로 뜸. 되살리기/접기 동작·다음 회고 반영.
- **의존**: S8(피드백 표현 공유)·v1 모멘텀.

### S10 · 연결 심화 (영감 신호)
- **목표**: 멀리 떨어진 생각이 한 줄기로 모이는 순간을 포착해 **실행 가능한 제안**으로.
- **포함**:
  - `relatedPairs` 고도화: 강도 티어(강/중) + **"새로 가까워진" 연결**(이번 주 처음 근접) 강조.
  - 연결 카드에서 바로 **"한 줄기로 묶기"**(=주제 합치기) 한 탭.
  - 주간/기간 서술에 연결 통찰 주입("멀리 있던 A와 B가 이번 주 만났어요").
- **데이터**: 모델 변경 없음(임베딩 기반 계산).
- **검증**: 관련 주제 쌍이 강도와 함께 표시, 묶기 동작, 서술에 반영.
- **의존**: v1 relatedPairs.

### S11 · 피드백 고리 가시화 ⭐ 루프 닫힘
- **목표**: 회고가 "지난 결정 이후 어떻게 됐나"로 시작해, 결정이 다음을 똑똑하게 만드는 게 보이게.
- **포함**:
  - 주간 회고 **최상단 "지난 회고 이후"** 요약: 직전 결정들의 현재 상태.
    - 지속한 X → 이번 주 N회(살아있음 ✓ / 조용함). 접은 Y → 다시 올라옴?(되살아남 알림). 약속(S8)들의 생존 합계.
  - 결정·약속 이력을 서술 입력에 넣어 "지난주 다짐한 것 중 …는 이어졌고 …는 흐지부지" 같은 통찰 생성.
  - 기간 정리에도 결정·실행 흐름 누적 반영(기존 결정 로그 확장).
- **데이터**: 기존 `Decision`·신설 `Commitment` 조회만.
- **검증**: 결정→1주 후 회고 상단에 추적 요약. 접은 게 다시 올라오면 환기.
- **의존**: S8·S9·S10.

# 생동하는 기록 (Living Record) — 사용 설명서

> 갱신: 2026-06-05 · 대상: 현재 빌드(v1 보관함 → v2 지속 루프 → v3 포착 도달성 → v4 검색 → 위키·되살아남·백업) · 플랫폼: iOS 26+ (iPhone)
> 근거: 실제 소스(`LivingRecord/`), 설계(`concept.md`), 검증(`spike-findings.md`), 계획(`v1~v4-slices.md`)

---

## 0. 이 앱은 무엇인가

말이나 글로 **생각을 흘려보내듯 포착**하면, 앱이 그것을 **로컬에 보관**하고 **비슷한 생각끼리 주제로 묶고**, 하루·한 주·한 기간 단위로 **돌아볼 거리(정리)** 를 만들어 준다. 궁극의 목적은 한 가지 질문에 답하는 것:

> **"나는 무엇을 지속할 것인가?"**

채점·평가 앱이 아니다. 판단은 사람이 한다. 앱은 **증거(반복·에너지·흐름)를 모아 보여줄 뿐**이고, 지속/보류/접기는 사용자가 정한다.

### 세 가지 흔들리지 않는 원칙
1. **포착은 마찰 0.** 분류·제목·태그를 묻지 않는다. 말하거나 쓰면 끝.
2. **로컬 우선.** 원문·음성·에너지는 기기를 떠나지 않는다. 클라우드는 *선택*이고, 나갈 때도 원문이 아니라 *요약(증류층)* 만 나간다.
3. **결정은 사람이.** AI는 분류·요약·신호 제시까지. "지속할까/접을까"는 사용자 몫.

---

## 1. 시작하기

### 1-1. 첫 실행
앱을 열면 바로 **포착 탭**이다. 설정 없이도 말하거나 입력해 바로 기록할 수 있다. 다만 두 가지를 미리 해두면 좋다.

### 1-2. Obsidian 볼트 연결 (선택, 권장)
포착·정리를 마크다운 파일로도 **동시에 남기고 싶다면** 연결한다.
- **포착 탭 우상단 톱니(⚙️) → 설정 → Obsidian 볼트 → "볼트 폴더 선택"**
- 폴더를 고르면 이후 모든 포착이 그 폴더 아래에 `.md`로 미러된다.
  - 일반 포착 → `Captures/`
  - 봉인 포착 → `봉인/`
  - 정리(일일/주간/기간) → `Digests/`
- ⚠️ **주의:** 볼트 폴더가 iCloud/드롭박스로 동기화되면 **봉인 포착도 기기를 떠난다.** 봉인의 의미(기기 밖으로 안 나감)를 지키려면 볼트는 로컬 폴더로 둘 것.

### 1-3. 클라우드 깊은 종합 (선택, 기본 꺼짐)
주간/기간 정리를 Claude로 더 깊게 종합하고 싶을 때만 켠다.
- **설정 → 클라우드 깊은 종합 → 토글 ON + Claude API 키 입력 → "키 저장"**
- 키는 기기 **Keychain**에 저장된다(코드·서버에 안 남음).
- 켜도 **원문은 안 나간다.** 로컬에서 만든 *주제별 요약(증류층)* 만 전송하며, **봉인 포착은 아예 제외**된다. 나간 내역은 설정의 **전송 기록**에서 날짜·종류·글자 수로 확인할 수 있다.
- 끄면(기본값) 모든 정리는 **온전히 로컬 AI(Apple Foundation Models)** 로만 만들어진다.

## 2. 화면 구성 — 5개 탭

하단 탭은 5개다. **빈 영역을 좌우로 쓸면** 옆 탭으로 넘어간다(좌→다음, 우→이전).

| **기록** | ☰ | 모든 포착을 최신순으로 본다 + 검색(전문·의미) |
| **주제** | ✚ | 자동으로 묶인 주제별로 본다 + 큐레이션 |
| **정리** | 📄 | 일일·주간·기간 회고를 만든다 (출구) |
| **흐름** | 📊 | 일별 포착·에너지 추이·주제 분포를 한눈에 |

**설정**은 포착 탭 우상단 ⚙️에서 카테고리별로: **저장 & 동기화**(Obsidian 볼트·백업), **정리 & 가공**(정리 템플릿·클라우드 깊은 종합), **알림**(저녁 회고), **도구**(받아쓰기 정확도).

### 2-1. 포착 탭 — 생각을 남기는 곳

화면 위에서 아래로: **봉인 토글 → 녹음 버튼 → 직접 입력칸**.

**① 음성으로 (기본)**
- 가운데 **마이크 버튼을 탭하면 녹음 시작.** "듣고 있어요 · 탭하면 저장"이 뜨고, 목소리 크기에 맞춰 링이 맥동하며 경과 시간이 보인다.
- **다시 탭하면 정지·저장.** 자동으로 받아쓰기(STT)가 돌아 텍스트로 저장된다. 가벼운 추임새("음/어/응" 등 단독 토큰)는 보수적으로 정리된다.
- 녹음 중 **음향 에너지(각성도)** 를 뽑은 뒤 **오디오 원본은 즉시 폐기**한다. (목소리 점수만 남고 음성 파일은 안 남는다.)

**② 글로 (폴백)**
- 아래 "또는 직접 입력" 칸에 쓰고 **저장**. 길어지면 칸이 아래로 늘어난다(최대 6줄, 그 이상은 내부 스크롤). 키보드 위 **완료**로 닫는다.

**③ 봉인 (🔒)**
- 위 **봉인** 칩을 누르면 보라색 봉인 모드. 이 상태로 저장한 포착은 **기기 밖으로 절대 안 나간다**(Obsidian은 별도 `봉인/` 폴더, 클라우드 종합엔 제외).
- 아주 사적인 생각용. 일반 포착과 같은 화면에서 자물쇠로 구분된다.

**저장 직후** 백그라운드에서 조용히: 임베딩 생성 → 주제 배정/생성 → (볼트 있으면) 마크다운 미러. 사용자는 기다릴 필요 없다. 저장하면 **"예전에 비슷한 생각"** 메아리가 잠깐 떠 과거의 나와 이어준다(봉인 제외).

**④ 앱 밖에서 한 동작으로** — 액션 버튼·Siri·AirPods("Siri야, 생동하는 기록에 포착")·홈/잠금화면 위젯·제어 센터로 트리거하면 앱이 포착 화면으로 열리며 **자동 녹음**(봉인 변형 포함). 저녁 회고 알림으로도(아래 그 밖의 기능).

> 톱니(⚙️)는 이 탭 우상단에 있다(설정 진입).

### 2-2. 기록 탭 — 모든 포착, 최신순

- 모든 포착을 시간 역순으로 본다. 각 행: 본문 + 날짜/시간 + (있으면)에너지 막대 + 주제 칩 + (봉인이면)🔒.
- **기간 칩**(상단): 오늘 · 1주 · 1개월 · 전체 · 기간(직접 지정)으로 좁혀 본다.
- **검색**(상단 검색창): **정확히 포함**(전문, 즉시) + **비슷한 기록(추정)**(의미 검색, 리턴 시) — 단어가 안 겹쳐도 뜻으로 찾는다.
- **행을 길게 누르면** 컨텍스트 메뉴:
  - **다른 주제로 옮기기** — 다른 주제 목록 중 선택, 또는 **새 주제로 추출**.
  - **기록 삭제** — 포착과 그 Obsidian `.md`까지 지운다. 그게 주제의 마지막 기록이면 빈 주제도 정리.

### 2-3. 주제 탭 — 자동으로 묶인 생각들

비슷한 포착이 자동으로 **주제(Theme)** 로 묶인다. 주제 묶기는 **온디바이스 AI의 best-effort**다(완벽하지 않음 — 아래 §5 참고). 그래서 **큐레이션(손보기)** 이 핵심이다.

- 목록: 주제 이름 + 포착 수. 탭하면 그 주제의 포착들(수동 정렬순).
- **주제를 길게 누르면**: **이름 변경**, **다른 주제로 합치기**.
- 주제 상세에서 **우상단 ⋯ 메뉴**: 이름 변경 / 합치기. 개별 **기록을 길게 누르면** 다른 주제로 이동·추출.
- 이름 변경·이동·합치기를 하면 Obsidian의 `[[주제]]` 위키링크도 자동으로 다시 써진다.

> 자동 분류가 어긋나도 괜찮게 설계됐다. **틀리면 손으로 옮기면 된다** — 그게 정상 흐름이다.

### 2-4. 정리 탭 — 돌아보기 (앱의 출구이자 핵심 가치)

우상단 **"정리 만들기"(✚) 메뉴**에서 셋 중 하나:

**① 일일 정리 (오늘)** — 로컬 전용
- 오늘 포착을 주제별로 모아 **통찰 중심 서술**(나열이 아닌 흐름)로 4~6문장.
- 직전 7일과 **이어지는 흐름(🔁 반복)** 을 연결해 무엇이 이어지고 무엇이 새로운지 짚음.
- 끝에 **내일 이어볼 질문** 하나.

**② 주간 회고** — 핵심 가치 ⭐ (앱의 심장)
시트로 열리며, 위에서 아래로 **"지속 루프"** 순서를 따른다 — 돌아봄 → 이어갈 것 → 놓을 것 → 다짐 → 연결 → 글:

1. **지난 회고 이후** *(돌아봄 — 루프를 닫는 머리)*
   - 지난번 내린 결정의 *지금*. **지속**한 게 이어졌나(이번 주 N회 ✓) / 조용해졌나, **접은** 게 다시 올라왔나(↑). 결정이 다음을 비춘다. *(한 주기 지나야 보임)*
2. **지속 후보** — 이번 주(7일) **2회 이상** 돌아온 주제들. 각 후보에 신호 배지:
   - **↑ 떠오름 / ↓ 식어감** — 최근 절반(3일) vs 이전 절반(4일) 활동률. *모멘텀.*
   - **🌱 진화 / 🔁 맴돎** — 생각이 옮겨갔는지(전·후반 임베딩 중심 거리).
   - **에너지 %, 열 ↑/↓** — 평균 에너지와 그 추세.
   - 정렬은 **지속 가치 점수**(반복 중심 + 모멘텀·에너지·진화 가산) 순.
   - 각 후보에 **[지속] [보류] [접기]** → 저장되고 다음 회고(1번)에 반영.
   - **선례**(🕘) — 전에 이 주제를 결정한 적 있으면 "30일 전 '보류' 결정 (3번째) → 그 뒤 4회 더"처럼 그 전적을 보여줌. *지금 누르기 전에* 과거가 거든다.
3. **❄️ 식어가는 줄기** *(가지치기)* — 한때 자주 다뤘는데(직전 2주 ≥3회) 요즘 조용해진(최근 ≤1회, 4일+) 주제. **[되살리기]**(다시 이어가기) / **[접기]**(놓아주기). *지속 = 이어가기 + 가지치기.*
4. **이번 주 다짐** *(실행 추적)* — 포착 속 "~하겠다/해봐야지" 같은 의도를 자동 감지해 모은 것. 같은 주제가 이어지면 **이어지는 중 ✓**, 10일+ 잠잠하면 **잠잠해짐**. (자동 감지 — 참고용)
5. **연결된 주제** *(영감)* — 서로 가까운 주제 쌍. **새 연결**(이번 주 처음 가까워짐)·**강/중** 배지 + **[한 줄기로 묶기]** 한 탭(작은 쪽을 큰 쪽으로 합침).
6. **주간 서술** — "주간 정리 생성"으로 회고 글 생성. 위 신호(돌아봄·떠오름/식어감·다짐·새 연결)를 엮어 통찰로. 클라우드 ON이면 ☁️ 깊은 종합(증류층만 전송), OFF면 로컬.

**③ 기간 정리** — 임의 구간
- 최근 N일(또는 전체)의 반복 주제 + **"내린 결정과 그 이후"**(이어짐/다시 올라옴/정리됨) 누적 로그를 종합. 큰 흐름 요약. 클라우드 옵트인 동일.

생성된 정리는 목록에 쌓이고(상단 **기간 칩**으로 좁혀 봄), 볼트가 있으면 `Digests/`에도 저장된다.

### 2-5. 흐름 탭 — 한눈에 + 되살아남

- **되새김** *(과거가 안부)* — 가만히 있어도 하루 한 번, 14일+ 이전의 포착 하나가 올라온다. **"N년/개월 전 오늘"** 또는 **"한동안 잊고 있던"**. (반추 함정 방지로 봉인 제외·시끄러운 최근 편향 없음)
- **오래 이어진 줄기** *(throughline)* — 한 번 불타고 끝난 게 아니라 **여러 시기를 가로질러**(30일+·서로 다른 3주+) 거듭 돌아온 주제. "내가 한결같이 마음 쓴 것."
- **차트** — 요약(포착·주제·평균 에너지·봉인) + 일별 포착 수(14일) + 에너지 추이 + 주제 분포(Top 8). *(Swift Charts)*

## 2-9. 그 밖의 주요 기능

- **저녁 회고 리마인더** — 매일 정한 시각, 그날의 **되새김을 담은 알림**(없으면 "오늘을 한 줄로"). 탭하면 흐름/포착으로. *기기 안에서만.* (설정 → 알림)
- **LLM 위키** — 볼트를 LLM이 길찾아 읽는 지식 베이스로. 주제마다 **허브 노트**(`Themes/<주제>.md`: 메타 + 결정 + 기록 목록 + 클라우드 "한눈에") + **`index.md`**(줄기 + 모든 주제). 새 포착·큐레이션 때 자동 갱신, 기존 데이터엔 **"위키 다시 빌드"**. AI 한눈에는 클라우드 옵트인(증류·봉인 제외). 단방향(앱→볼트). (설정 → Obsidian 볼트)
- **암호화 백업·복원** — 전체 데이터를 암호로 잠근 파일 하나로 내보내기/복원(봉인 포함, 같은 암호로 병합). (설정 → 백업 & 복원)
- **정리 템플릿** — 정리 글의 톤·초점을 고르거나 직접 만든다(따뜻한 통찰/간결/질문 중심/행동 제안 + 자유 작성). (설정 → 정리 템플릿)

## 3. 핵심 개념 정리

| 개념 | 뜻 | 어떻게 쓰나 |
|---|---|---|
| **포착(Capture)** | 한 조각의 생각(음성→텍스트 또는 직접 입력) | 포착 탭에서 만듦 |
| **봉인(Sealed)** | 기기 밖으로 안 나가는 포착 | 포착 시 🔒 토글 |
| **에너지** | 말할 때의 각성도(음량 기반 0~100%) — *감정 분석 아님* | 자동, "평소 대비"로 해석 |
| **주제(Theme)** | 비슷한 포착의 묶음 | 자동 + 손으로 큐레이션 |
| **모멘텀** | 최근 흐름(떠오름/꾸준/식어감) | 주간 회고 배지 |
| **진화/맴돎** | 생각이 발전했나/제자리인가 | 주간 회고 배지 |
| **지속 후보** | 자주 돌아오는 주제 | 주간 회고에서 결정 |
| **결정(Decision)** | 지속/보류/접기 | 회고 글·기간 정리에 반영 |
| **다짐(Commitment)** | 포착 속 자동 감지된 의도 | "이번 주 다짐"에서 생존 추적 |
| **냉각(식어가는 줄기)** | 한때 뜨거웠다 조용해진 주제 | 되살리기/접기로 가지치기 |
| **연결(Connection)** | 가까운 두 주제(영감) | "한 줄기로 묶기" |

> **지속 루프**: 포착 → 주제 → 신호(반복·에너지·진화·**실행·냉각·연결**) → 결정 → 실행 추적 → "지난 회고 이후"로 피드백. 이 고리가 앱의 핵심 가치 "무엇을 지속할 것인가"를 돕는다.

## 4. 프라이버시 — 무엇이 어디에 있나

```
[음성] ──녹음──▶ 에너지 점수만 추출 ──▶ 오디오 즉시 폐기 (파일 안 남음)
                                          │
[텍스트/전사된 글] ──▶ SwiftData(기기 로컬) ──▶ (선택) Obsidian 볼트 .md
                                          │
                       ┌──────────────────┴───────────────────┐
                  기본(클라우드 OFF)                  클라우드 ON(선택)
                  모든 정리 = 로컬 AI               주간/기간만 = Claude
                                                   단, 원문 X → '증류층'(주제별 요약)만 전송
                                                   봉인 포착 = 항상 제외
                                                   전송 내역 = 설정에 기록
```

- **2단계 증류:** 원문은 로컬에만. 클라우드엔 로컬 AI가 만든 *요약*만. 원문 인용 없이 추상화.
- **동의 모델:** "한 번 켜기 + 봉인 예외 + 전송 로그". 매번 묻지 않되, 봉인은 늘 빠지고, 나간 건 다 보인다.
- 비밀키는 **Keychain**, 코드에 하드코딩 없음.

## 5. 알아둘 한계 · 주의 (정직하게)

- **실기기 전용 기능:** 받아쓰기(SpeechTranscriber)는 **시뮬레이터에서 음성 에셋이 취약**하다. 음성 포착은 실제 iPhone에서 테스트할 것. (실기기 실음성 문자 정확도 ≈ 92.8% 측정됨.)
- **자동 주제 분류는 best-effort:** 온디바이스 AI(Foundation Models)는 환경에 따라 한 주제로 **쏠리거나 과하게 갈라진다.** 그래서 설계가 "자동 + 큐레이션"이다. **어긋나면 주제 탭에서 손으로 옮기는 게 정상 흐름.**
- **FM 가드레일:** 무해한 문장도 가끔 로컬 AI가 거짓 차단할 수 있다(요약/이름짓기 실패 시 개수·앞글자 폴백으로 처리). MLX 오픈모델 폴백은 검증됐으나 v1 앱엔 아직 번들 안 됨.
- **신호는 데이터가 쌓여야:** 진화/맴돎은 임베딩 3개+, 에너지 추세는 에너지 포착 4개+, 모멘텀·지속 후보는 7일 내 2회+, **냉각**은 직전 2주 3회+ 뒤 조용, **다짐 생존**은 10일, **피드백("지난 회고 이후")**은 결정 후 한 주기가 지나야 의미가 생긴다. 초반엔 배지가 적게 보이는 게 정상.
- **의도 감지는 어미 게이트(결정적):** "~하겠다/해야지/해보자" 같은 한국어 의도 어미로 잡아 환경에 안 흔들린다(FM Bool 판정은 불안정해 버림). 드물게 과발화 가능("좋겠다"=소망)하고, 다짐 *라벨*은 FM이 뽑아 품질이 들쭉날쭉할 수 있다. 신호의 **임계값들은 실사용 데이터로 튜닝 예정**(현재는 보수적 기본값).
- **iCloud 볼트 = 봉인 유출 위험:** §1-2 주의 참고.
- **단일 기기:** v1은 기기 간 동기화 없음(iCloud 동기화는 후속). 백업은 수동.

## 6. 데이터 모델 (한눈에)

- **Capture** — 한 포착: 텍스트, 생성시각, 에너지?, 봉인여부, 태그후보, 임베딩(512d)?, 주제?, 정렬값.
- **Theme** — 주제: 이름, 상태(활성/맴돎/냉각/결정됨), 포착들, 위키 "한눈에" 요약?.
- **Digest** — 정리: 종류(일일/주간/기간), 기간, 서술글, 클라우드생성여부.
- **Decision** — 결정: 주제, 판정(지속/보류/접기), 시각.
- **Commitment** — 다짐(의도): 의도구, 시각, 상태(진행/이어짐/잠잠), 주제ID 스냅샷.
- **CustomTemplate** — 사용자 정리 템플릿: 이름, 스타일 지시.
- **Transmission** — 클라우드 전송 로그: 종류, 글자 수, 시각.

> 향후 채점/코멘트 등 확장 테이블을 붙일 수 있게 모델은 열려 있다.

## 7. 기술 스택 (참고)

SwiftUI + SwiftData / Apple 온디바이스 AI 올인:
- STT = **SpeechTranscriber** (한국어 on-device)
- 로컬 LLM = **Foundation Models** (+MLX 폴백 예정)
- 임베딩 = **NLContextualEmbedding** (한국어, *중심화 전처리 필수*)
- prosody = **vDSP** 음향특징(각성도)
- 로컬 텍스트 생성 = **LocalSynth**(FM → MLX 폴백 자리) · 깊은 종합(옵트인) = **Claude (Sonnet)** = `CloudSynthesizer`
- 핵심 컴포넌트는 **인터페이스로 추상화**(Transcriber/ProsodyAnalyzer/Embedder/ObsidianMirror/IntentionDetector) → 교체 가능.
- 검색·신호 = **NLContextualEmbedding**(중심화) 코사인 + 결정적 신호(어미 게이트·날짜창). *주제 간 자동 연결은 임베딩 신뢰 불가로 미채택.*

```
총점(100) = 주간 30 + 스파이크 15 + 에세이 15 + 감사 10 + 기말 30
각 평가물 = Σ(항목 수준점수 × 항목가중치) → 0~100 환산
```

| 등급 | 총점 | 기술(記述) |
|---|---|---|
| A | 90+ | 판단·검증·프라이버시를 *스스로* 짚는다 |
| B | 80–89 | 근거 있게 충실히 수행 |
| C | 70–79 | 동작하나 근거·검증 얕음 |
| D | 60–69 | 미완·따라치기 다수 |
| F | <60 | 핵심 미달 |

## 8. 채점 운영 메모 (강사용)

- **부분점수·재제출:** "범위를 좁혀 완성"은 감점이 아니라 **E 역량 가점**. 마일스톤은 1회 재제출 허용(상한 우수).
- **표절·따라치기 방지:** *왜* 질문을 발표·질의응답에서 즉석으로 — 근거를 못 대면 C 이하.
- **공정성:** 실기기 부족으로 음성/위젯/알림을 못 한 경우, 시연 대체·로직 설명으로 대체 평가(작동성 비중 완화).
- **피드백:** 점수보다 *역량 A~E별 한 줄 코멘트*를 우선 — 다음 마일스톤에서 무엇을 고칠지.
- **가중치 조정:** 분반 수준에 따라 기말 비중(30)과 주간 비중(30)을 ±10 내에서 조정 가능.
